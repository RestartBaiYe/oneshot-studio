# 原四步工作台 · 双模型制片

基线是 0bd75329：案例展厅、四步任务场记单、规则审查、离线示例与黑场技术检查保留。真实 AI 分镜和视频任务在这些页面内有独立状态；演示脚本批准不等于生成式视频批准。不会从商品图做平移/缩放动画。

## 第一次使用
1. 双击 media-service/start.bat，在本机打开 http://127.0.0.1:41739/。需 Node 18+。FFmpeg / FFprobe 用于验证、剪接云端返回的 MP4；可用 FFMPEG_PATH、FFPROBE_PATH 配置。公开 Pages 可看展厅、试跑离线脚本，不接收双模型密钥。
2. 左侧「模型配置」：文字／识图栏填 HTTPS Base URL（API 根地址，例如 https://api.openai.com/v1 或方舟 https://ark.cn-beijing.volces.com/api/v3）、支持 image_url 图像输入的模型 ID 和该端点的 Key。视频栏填方舟北京 Seedance 接入点 ID 与方舟视频 Key。两者均为方舟时才可勾选共用。只填视频 ID 不能代替视觉模型。保存不会探测或产生费用。
3. 展厅点「用商品图做 AI 视频」。选择有权使用的原始 JPEG/PNG（≤8 MB），填写介绍，确认上传及可能的费用。模型同时收到图片与介绍；只有得到有效的商品观察和四镜剧本才进入分镜页。每镜有场景、文案、视频提示词，可编辑或下载 JSON。
4. 审查页对照原文、核对四镜并批准；批准不会提交视频。第 4 步逐镜确认提交：当前批准的提示词与同一商品原图作为 first_frame，5 秒、adaptive。每次只发一条，支持查询同一 task_id，失败不会自动创建新的任务。提交结果未知时先在方舟控制台核对，再绑定原任务号。
5. 四个可解码的真实视频文件均就绪后剪接成 720×1280 MP4；另附实际片长时码 SRT 与含提示词、任务号的 storyboard.json。不是生成新的商品图；视频模型仍可能改变商品细节，发布前请人工检查。

## 凭据与本地数据
两份 Key 只在本机服务进程内存中使用，不回显、不写模型配置文件。端点、模型 ID 保存到 deliveries/.ark-private/models.json；改变文字端点不会把旧 Key 发到新地址。环境变量可用 VISION_BASE_URL、VISION_API_KEY、ARK_VISION_MODEL、ARK_API_KEY、ARK_VIDEO_MODEL。只有选择受信任供应商后才发送图片。配置与任务接口只接受回环服务的同源请求。DSH 宿主凭据不自动导入。不要将本机服务代理到公网或在聊天中贴 Key。

新任务在本机保存；恢复上次项目或通过 /?project=项目号 打开。切换新任务不取消已经提交的云计费。模型 Key 不进 Git/压缩包；项目图像和真实镜头也不发布。没有成功的云片段时不会用样例片或模板替代。旧版比赛文档、样片和旧版测试仅代表相应发布版本。

## 可复验的工程证据

## 商业商品广告的四镜职责与重做

整组策划围绕一个可证实的购买理由：第 1 镜亮相和需求，第 2 镜说明购买理由，第 3 镜视觉佐证，第 4 镜产品定帧和行动引导。未知的折扣、售价、权威背书或功效不得补造。没有活动资料时仅邀请查看详情。图文模型、单镜优化、审批时显示的最终提示词、DSH 交接及 Seedance 直接提交共用这个广告目标。它约束模型意图，不保证生成结果或法律合规。已有已批准/在途的旧版项目不静默追加规则。

未出片时分镜卡是商品原图与拟用文案，仅作参考。手改后可只保存本镜；整组未批准可重新策划。针对一镜填写方向进行优化，或选择重新构思；两者只调用图文模型。查看原稿与候选，采用或丢弃；批准后的镜头修改需要重新批准。不重新制作其他镜。已就绪时真实片段可播放、拖动；重做已完成镜头不立即收费，重新付费需另按提交。重做使该镜及本次合并结果失效，旧版本与任务编号保留在尝试记录中；已下载文件无法远程撤回。方舟明确失败、取消、过期可单镜重提；排队、生成中、结果未知先查原任务。

## 正式任务与案例边界

「当前任务」恢复本机项目：有待批改单进审查、已有批准或成片进交付、有草稿进分镜，否则进素材。「商品图 AI 制片」始终打开同一项目的商品素材，不清空草稿或已有镜头。正式四步有独立页面；正式模型配置只显示图文与视频两栏。离线脚本、规则记忆和示例设置只属于展厅案例，不代表本次模型调用。
