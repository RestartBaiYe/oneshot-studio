# 哪项工作值得自动化

上新、改价、促销时，电商运营收到商品原文与图片，需要把可用卖点交给剪辑或投放同事。OneShot 起草四镜稿、筛查部分主张并修订；人决定是否批准和发布。已有成片走独立技术检查。

## 工程基线与验收目标（不是商家收益）

基线：前一发布版 79358abc 的固定案例与回归记录；目标是在本次冷启动、无付费模型条件下至少保持同等表现。

| 指标/样本 | 基线 | 本轮目标 | 证据 |
|---|---:|---:|---|
| 咖啡注入错误后复核轮数 | 2 | 2，且仅改错的 1 镜 | tests/runtime.cjs |
| 通勤杯脚本的批准操作 | 1 次 | 1 次；拒绝则 0 个可导出文件 | result.metrics、批准/拒绝回归 |
| 咖啡新片字幕与已批准脚本逐句一致 | 4/4 | 4/4 | tests/ui.cjs 的实际下载比对 |
| 新片实际可领取文件数 | 5 | 5，均非空 | tests/ui.cjs |

每次脚本任务导出的运行证据 JSON 的 result.metrics 区分 activeMs、humanWaitMs、reviewRounds、approvalDecisions、scriptFiles。activeMs 不含人工等待，不等于业务端到端耗时。

## 商家试用登记（未测，不填零）

用脱敏的同等复杂度商品，为人工与工作台两组交叉分配；计时从收到资料到复核人判定可用，拒绝、失败和人工修改都要记。每行记录商品匿名号、操作人匿名号、方法、起止时间、返工次数、盲审可用与否、失败原因。不公开原始商家数据。试用目标（非实绩）：先收集至少 5 对任务；比较中位完成时间和返工次数，目标为时间下降 ≥20%、可用率不低于人工。实际人工基线、样本量及效果仍待试用。
