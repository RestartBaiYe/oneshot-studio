# 单机业务试用与恢复

旧流程：运营整理事实 → 手写文案 → 逐条复核 → 交给剪辑 → 检查成片。试用流程：运营给 brief/素材 → Agent 起草、工具初筛、有限修订 → 运营核对原文并批准 → 本机编码 → 剪辑拿 MP4/SRT/封面/分镜和报告 → 人决定发布。无自动上架接口。

解压运行包；准备 Node 18+、FFmpeg（libx264、drawtext）、FFprobe、可读中文字体。Windows 双击 media-service/start.bat；自定义路径用 FFMPEG_PATH、FFPROBE_PATH、ONESHOT_FONT 或 ONESHOT_PORT。在 localhost 页面完成整条链路，离线无需模型。启动时实际编码三帧并用 FFprobe 核对；失败不会亮绿灯。端口被占用时先核对原进程，不强制杀用户进程。关闭服务窗口即停止服务，可重启。

安全边界：单人可信机器；仅监听回环，限制 Host / Origin，媒体留在本机，审查完成删除源视频，交付目录由运营按试用周期清理。审批属于工作台，不声称本机 HTTP API 有多用户鉴权。文件一旦已下载不能远程撤回；输入变化后作废工作台链接，可重新审批制作。不要把媒体服务或密钥通过公网代理共享。自带文本模型会把 brief/上下文发送至所选端点；key 仅驻当前页面内存。使用 HTTPS、受信任服务商；多用户生产需要单独的鉴权、隔离与服务端密钥代理。

预算：单次任务 1–8 次模型请求（默认 4），每次最多 900 个输出 token，输入不超过 24000 字符；达到上限不发下一次请求，不偷偷切离线。按提供方返回 token 与自填人民币参考价显示估算；缺用量、价格或请求失败则总费用未知。不是人民币硬限额，生产硬账单上限请在提供方账户配置。
